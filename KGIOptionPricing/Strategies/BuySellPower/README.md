# 買賣力道（指標觀測）

在模擬策略中心或實盤策略中心的「買賣力道」頁籤，按「啟動觀測」同時計算 225、225M、225MC。兩個中心共用觀測服務，頁籤操作不建立券商委託。實際合約由既有熱門合約解析取得。

每個商品各自設定五個參數，按「套用／重新暖機」保存設定並用新實例重新計算；舊實例停止，既有 CSV 保留。暫停時保存未完成段；恢復重新暖機。尚無有效成交時顯示「尚無資料」。

| 參數 | 預設 | 合法範圍 |
|---|---:|---|
| PowerWindowSeconds | 30 秒 | 1–3600 |
| ShortAverageSeconds | 60 秒 | 1–86400 |
| LongAverageSeconds | 180 秒 | 短期秒數–86400 |
| ReversalPoints | 30 點 | 大於 0 且不超過 10000 |
| MovementAveragePeriods | 20 段 | 1–10000 |

暖機由第一筆有效成交開始，預設力道視窗在 30 秒完整，短期平均在 90 秒完整，長期平均在 210 秒完整。平均為 BuyPower 的時間積分除以秒數；無成交時也處理精確到期點。BaisPower = 短期平均−長期平均，單位為百分點；長期平均為零仍可計算，長短期尚未完成暖機時不顯示數值。

報價須為正且買一小於賣一。成交價 >= 賣一為 UPTICK、<= 買一為 DOWNTICK、中間為 ZEROTICK。單筆正口數的 10 倍數與無效資料不參與力道或行情段，跳過計數顯示在畫面。

UpTick、DownTick、ZeroTick 的分母為視窗內三類有效成交的總口數，顯示百分比至小數四位；ZeroTick 吸收四捨五入餘數，使三者合計 100%。BuyPower = UpTick百分比 − DownTick百分比，長短期平均也使用此百分比做時間加權。空視窗顯示「尚無資料」，平均積分以 0 計入空視窗持續時間。

第一筆有效成交固定為起點 X，反向門檻為 Y。成交首次達到 X+Y 時建立第一段上漲，首次達到 X−Y 時建立第一段下跌；未達門檻時維持「未定」，不移動起點或保存短段。已建立段在振幅 >= 門檻且反向 >= 門檻時完成（包含剛好 30 點，避免新段反轉後無法結束）。前段極值是新段起點，反向確認成交直接計入新段。完成段秒數從起點到極值，確認結束時間另存。

既有保存的反轉點數不會被新預設值覆蓋；如要將舊設定改為 30 點，於頁籤修改後按「套用／重新暖機」。

歷史根目錄顯示於畫面，預設位置為應用程式目錄下：

```text
買賣力道歷史/
  實例ID-唯一執行ID/
    商品/合約/
      時段開始日期/日盤或夜盤/行情段紀錄.csv
```

參數設定保存為應用程式目錄下的 `buy-sell-power-settings.json`。CSV 使用 UTF-8 BOM，含完成旗標、結束原因與五個生效參數。UI 顯示各商品當時段最近 500 段；CSV 保存全部。跨時段清指標與當時段平均，未完成段保存但不計平均。日盤台灣時間 07:45–14:45、夜盤 16:00–翌日 05:00；夜盤目錄日期是時段開始日期，與交易所結算交易日分開。

保存使用有上限的背景佇列；磁碟錯誤或佇列滿會顯示「保存異常」。停止時等待待寫資料完成。檔案異常狀態不等於全部歷史已保存，不應忽略。

## 時間精度限制

`MarketEvent.Timestamp` 目前是行情接收時間。券商 `TradeTime` 原始時刻另存 `SourceTradeTime`，但沒有已驗證的日期／時區，因此本版指標與行情段一律使用接收時間。UI 明確顯示來源。舊封存沒有 `SourceTradeTime` 可繼續重播。後續取得券商時間契約後，才可增加正式交易所成交時間模式。

## 驗證與分析

```powershell
dotnet run --project tests/BuySellPowerSmokeTests --no-restore -p:UseSharedCompilation=false
python tests/BuySellPowerSmokeTests/test_analysis.py
python KGIOptionPricing/Strategies/BuySellPower/analysis/analyze_buy_sell_power.py <歷史目錄或CSV> --mode all --output <輸出前綴>
```

分析腳本只讀 CSV，依商品、合約、時段和參數分組，分方向計算最近 N 個完成段的平均，產生 JSON 與 Markdown。未完成段排除，沒有進出場邏輯，因此不產生獲利評估或交易參數推薦。
