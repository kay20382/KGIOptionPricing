# 實盤策略手動關閉、刪除與程式結束設計

日期：2026-09-24

## 目的與適用範圍

使用者按「關閉策略」時，程式停止該實例的新訊號，撤銷該實例仍在市場上的委託，並在券商確認無有效委託後停止策略。有未平倉部位時僅提醒，不因手動關閉、刪除或結束主程式送出平倉單，也不修改策略帳本口數。使用者明確要求在策略帳本仍顯示部位時，仍可刪除策略及結束主程式。

此流程適用於操作者主動按下的關閉、刪除與主程式結束。策略執行期間既有停損、單日虧損與收盤前風控屬於不同事件，不由這個按鈕重新定義。手動在其他介面成交的委託仍為無策略歸屬，不得偽造成策略成交；缺少成交明細時，策略最後損益必須顯示「待對帳」。

## 目前問題

`LiveStrategyService.RequestClose` 會授權自動 `Flatten`；即使帳戶已由人工平倉，策略帳本仍可能顯示 `-1` 口，重試流程便可能再送買單。`GetShutdownWarnings` 與執行器釋放規則又將內部部位和等待晚到成交的終結委託當作禁止結束條件。`LiveStrategyCenterForm.Delete` 要求部位為零，造成手動平倉後無法刪除。終結委託觀察紀錄與有效市場委託必須分別揭示。

## 方案選擇

1. **停止並留存紀錄（採用）**：移除執行中的策略實例，保留不可變的訂單歸屬、最後帳本快照及操作確認紀錄；晚到或未知券商回報隔離，重啟時不得自動恢復交易。使用者已選定此方案。
2. 直接清除策略及歸屬資料：操作較少，但晚到成交無法回到原實例，與多策略同商品歸屬規則衝突。
3. 維持部位歸零及晚到成交紀錄全部過期才可結束：保護最嚴，但無法完成使用者明確要求的關閉、刪除與退出。

## 手動關閉流程

1. 對選取的 `StrategyInstanceId` 與執行世代設定「使用者關閉、不自動平倉」的關閉模式，先阻止新的訊號、限價單、既有自動平倉重試與後續風控平倉請求。模式轉換必須與正在送出的委託序列化；不能在一張平倉單已跨過送券商邊界後仍宣稱沒有送單。
2. 清除該實例本機尚未觸發的條件，只撤銷該實例仍有效的券商委託。其他策略、手動單及不同世代的委託不受影響。
3. UI 顯示有效委託數、撤單中數、等待晚到成交觀察數、策略帳本部位與所屬帳號／合約。若撤單尚未由券商確認，維持「關閉中」，說明阻擋原因；不以本機送出撤單請求當作已撤單。
4. 確認有效委託與本機條件均為零後，將策略標為 `Stopped`。若帳本仍非零，`Reason` 明示「已停止；帳本部位待人工對帳」，顯示確認警告。保留的晚到成交觀察紀錄不視為有效市場委託，不再單獨阻止手動停止。
5. 若回報顯示有效委託狀態不明、撤單失敗或協定異常，維持關閉中並顯示具體原因；不得把不明委託視為零。

## 刪除與帳本

「刪除策略」從活動策略列表移除已停止的實例；先要求該實例有效委託與本機條件為零，再向持久化日誌追加 `RetiredStrategy` 紀錄，包含實例、世代、帳號、合約、最後策略帳本口數、已實現／未實現損益、費用、未結算觀察數、操作時間及操作者確認。持久化失敗不得移除實例。

刪除不將非零部位改為零，不產生虛構成交或損益。活動帳本移除該實例的計算入口前，完整快照寫入退休紀錄；歷史歸屬路由及成交去重水位仍保留。若部位非零，最後損益標記為「待對帳」，不得作為已實現策略績效。刪除後收到可追溯的晚到成交，只能寫入該退休實例的隔離／審計紀錄，不能分配給另一個策略。

## 主程式結束與重啟

主程式結束前列出各實例的有效市場委託、待觸發條件、帳本部位及晚到成交觀察數。使用者確認退出後，先對所有仍在運行的實例進入相同的「使用者關閉、不自動平倉」模式，阻止新的訊號與委託；存在有效委託或待觸發條件時走撤單流程並等待確認。若狀態不明則阻止結束。只有部位或已終結委託觀察紀錄時，提供明確警告並允許使用者確認結束。確認後寫入退出審計紀錄，再釋放服務；退出流程不得呼叫會自動 `Flatten` 的緊急停止路徑。服務釋放失敗時不可吞掉例外後強制 `Environment.Exit`。

重新啟動後，退休實例不自動恢復、不得重新使用相同執行世代；持久化路由用於辨識晚到成交或不明券商回報。未完成的券商與策略帳本差異標記為需要對帳，在重新查核以前不把歷史非零帳本部位視為實際券商持倉，也不將其分配給其他策略。

## UI 與可觀測性

- 按鈕更名為「關閉策略（撤單）」；確認視窗分列有效委託、本機條件、晚到成交觀察及帳本部位，明示此操作不平倉。
- 「刪除」對非零帳本部位顯示最後警告與待對帳標記；成功後從活動表格移除，審計紀錄保留可查。
- 拒絕關閉、刪除或退出時顯示具體的委託、撤單、持久化或併發阻擋原因，避免一律顯示「不符合安全條件」。
- 不以 `QuarantinedBrokerOrderCount` 代替有效市場委託數；兩者分開顯示。

## 驗收與測試

- 以一口空單、帳本仍為 `-1` 且券商端手動平倉的案例驗證：按關閉後不新增任何券商買單；有效委託確認撤銷後可停止、刪除與結束程式。
- 同帳號同合約兩個策略同時存在時，只撤選取實例的訂單；刪除後晚到成交不得歸給另一策略。
- 以大量已終結委託觀察紀錄驗證其不被算成有效委託；若仍有真正有效委託或撤單失敗，停止、刪除及退出要顯示具體阻擋原因。
- 驗證持久化失敗、送單與關閉競速、晚到成交、重啟回補、無成交明細損益標記，以及應用程式退出不呼叫自動平倉。
- 驗證單日虧損或收盤風控在手動關閉開始後不能重新啟動自動平倉；未進入手動關閉的運行中策略仍遵循原風控規則。
- 聚焦測試先失敗再修正，最後執行相關策略／下單冒煙測試及 Debug／Release 建置；驗證使用測試轉接器，不送真實委託。
