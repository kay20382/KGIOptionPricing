# MR 雙側常駐限價與可選均線平移設計

日期：2026-09-27

## 目的與已確認需求

修改既有 `MeanReversionScalper`，不是建立平行策略引擎。每輪在原有 H 秒區間、R、F、K、時段與資料健康門檻通過後，同時送出買、賣兩張 225MC 限價單。第一側成交後，對側原委託不撤單、不重掛，直接承擔該輪的反向限價出場；此時建立本機停損觸價條件。停損觸發後，先撤對側委託，等券商終態與成交水位對平，再依策略剩餘部位送一次市價停損。

移除「225M 與 225 同向」判斷。只有一個可選的「使用均線」開關；關閉時兩側仍可進場。開啟時，均線只決定兩側價格共同上移或下移 N 跳，不刪掉任何一側。N 可自動縮小，使買單不高於有效買一、賣單不低於有效賣一，兩側價差及相對停損距離不變。實盤兩側限價使用券商自動開平倉語意。

成功標準是模擬與實盤轉接器對同一輪有一致的委託身分、成交歸屬及停損競態處理；多策略同商品並行時不得按商品或帳戶淨部位猜測回報歸屬。程式、測試與歷史重播完成不代表獲利或券商端行為已驗證。

## 範圍與既有契約

沿用 `StrategyDefinition`、`StrategyRuntimeContext`、共用策略帳本、商品解析、共用市場封存及執行紀錄。225MC 預設 tick 為 5 點、乘數為每點 ¥10；每次每口成交手續費 ¥36。跳動點與乘數仍以解析後商品規格為準，不在策略硬編碼。共用帳本依實際成交價計算損益；策略不得另算具權威性的損益。

維持現有 H=600 秒、F=0.6、K=1.2、最小 R=8 跳、最大 R=20 跳及可設定時段。H 不因成交、冷卻或無部位重新起算。既有收盤前停止新單、精確撤單及剩餘部位風險平倉規則不放寬；跨時段重新暖機。模擬維持嚴格穿價成交及委託價成交，取消委託不額外計費。

不變更其他策略的進出場語意，不把一張券商委託改寫成另一張，也不依賴未確認的券商原生 OCO。暫停／刪除策略、關閉程式和帳戶級風控仍由既有共用服務處理。

## 已考慮的做法

1. **採用：顯式雙側常駐模式。** 同輪兩張原始 BrokerLimit 委託保持各自 immutable client/broker 身分；共用執行層按週期與已確認策略部位判定第二筆成交的有效用途。停損另走精確撤單、結算、市價平倉狀態機。可符合不撤單重掛要求，但需要修改共用 OCO 與紀錄語意。
2. 券商原生括號／OCO：若券商能力已驗證，可減少本機競態，但現有程式沒有可依賴的該能力，不能當成本次前提。
3. 首側成交後撤對側、重掛 TakeProfit：沿用現有結算流程較容易，但違反本次「原單不撤不重掛」，不採用。

## 參數與均線訊號

- `UseMovingAverage`：布林，預設 `false`。關閉時不要求 225 或 225M 報價才能產生新輪；兩側平移為 0。
- `TrendShiftTicks`：非負整數，預設 1、允許 0–20；UI 明確顯示「設定 N」與「本輪實際 N」。值不隱含策略績效承諾。
- `MovingAverageReferenceProductId`：預設 225M；均線開啟時必須能從設定的參考商品解析到唯一合約，否則啟動前拒絕。均線關閉時此欄不構成資料依賴。
- 均線開啟時，使用該參考商品最近 H 秒的每秒中間價 SMA：對每個完整的一秒區間取截止時最近一筆有效買賣簿的中間價，且該筆報價距區間終點不得超過既有 `FreshnessSeconds`；若 H 秒中任一秒無有效樣本，則拒絕該輪並記錄資料缺口。現價高於均線為向上、低於為向下、相等為中性（N 實際為 0，但仍可雙側掛單）。225 不參與同向確認；使用者可更換商品與參考商品設定。
- 策略既有 R、價差、新鮮度、時段、冷卻及帳戶風控條件仍必須通過；均線勾選不取代它們。

## 價格與被動掛單約束

以同輪凍結的中心價 `P0`、225MC H 秒區間 `R`、解析後 tick `T` 計算未平移價：

```text
L0  = roundDownToTick(P0 - R*F/2)       // 買進
U0  = roundUpToTick(P0 + R*F/2)         // 賣出
SL0 = roundDownToTick(P0 - R*K/2)       // 多單停損
SS0 = roundUpToTick(P0 + R*K/2)         // 空單停損
```

向上／向下趨勢分別令 `s=+1/-1`，中性或均線關閉令 `s=0`。只在整數 `n` 屬於 `[0, TrendShiftTicks]` 中選擇**最大**且同時滿足下式者：

```text
d = s*n*T
L = L0+d <= 目前有效 bid1
U = U0+d >= 目前有效 ask1
L > 0, U > L
SL = SL0+d, SS = SS0+d
```

這使 `U-L`、`L-SL`、`SS-U` 對同輪保持不變。若連 `n=0` 也不符合有效簿與被動價條件，拒絕整輪，不能單側先送或偷偷改 F／K。送單前再次核對報價新鮮度與上述不等式；兩側依同一份有效報價及同一個凍結位移計算。市場在檢查和券商接受之間可能變動，故此規則只能避免**檢查當下**的可立即成交價，不能保證交易所端絕不迅速成交。任一側送單失敗、結果不明或另一側未送出時，立即停止該輪後續新單，精確處理已送的一側，直到券商回報及部位對平；不得假裝原子雙單已建立。

## 雙側原單生命週期

兩張一口 `BrokerLimit` 具有相同 `StrategyInstanceId`、執行世代、`CycleId` 及成對識別，買／賣各有唯一 `ClientOrderId`。此模式不得沿用「EntryLong 與 EntryShort 為 OCO、首側成交即取消另一側」的舊行為；其他策略原有 OCO 行為不變。

首筆可唯一歸屬的成交確定輪次方向並進入持倉狀態，對側原單仍在市場上，視為該輪的**待成交限價出場**，價格及 broker/client ID 均不變。策略立即依實際已確認淨部位及凍結的 `SL` 或 `SS` 建立本機停損觸價條件。原始委託角色與券商路由 metadata 永遠保留；成交紀錄另保存「本筆對策略的有效用途」（首次進場或對側停利出場），不得在事後改寫原券商委託身分。共用帳本只按已唯一歸屬的實際成交更新部位與費用。

若成交回報順序不足以唯一辨認首次進場／後續出場，或兩側累積量與策略帳本不一致，將該輪置於隔離／待對帳，禁止下一輪，保留兩張委託與所有回報識別供核對。重複或晚到成交必須冪等；同一帳戶商品的其他策略委託不得作為判斷依據。對側完整成交使策略部位歸零時，精確取消本機停損條件，待兩腿委託與帳本結清後才進入冷卻；不額外送 TakeProfit 券商委託。

實盤兩張預掛限價以 `PositionEffect.Auto` 送券商，不在送出時以當下帳戶淨部位強制標成 Open／Close。此僅決定券商端開平倉語意，**不**取代以策略實例、委託 ID、券商 ID 與成交水位做歸屬和帳本對帳。券商對 Auto 的實際接受、淨額及跨策略行為仍需受控驗證；發現不一致時隔離，不自動調整其他策略部位。

## 停損、時段截止與故障處理

本機固定 `StopLoss` 條件於首側實際成交後建立；它不是在交易所預掛的原生 stop order。觸價後鎖住週期並停止新單，精確撤銷仍工作的對側原限價單。只有券商終態含可用最終累積成交水位、且所有已成交量已交付共用帳本並相等時，才重新讀取**該策略**剩餘淨部位。若已歸零，不送市價單；否則只對剩餘數量送**一次**市價 `StopLoss`。撤單期間對側晚到成交須先入帳；部分成交按剩餘數量處理。撤單失敗、未提供可靠水位、送單結果不明或 broker/strategy 對帳差異時，不猜測已撤，也不盲送第二張市價單，轉為待人工處理並明確告警。

排程停止與收盤前風險平倉沿用既有時間規則：停止新進場，精確撤當輪仍在市場上的委託，確認終態和成交水位後，才對該策略剩餘部位平倉。取消／平倉競態使用同一個週期狀態機，不能一邊完成停損、一邊又提交時段平倉。已凍結的價位、H 計算與下一時段暖機規則不因本模式改寫。

## 重啟回補與可觀測性

持久化原始雙腿身分、實際 N、凍結價、首次成交側、累積成交與已交付水位、本機停損、待撤單、已送市價 intent 及週期階段。重啟後先暫停並向券商查工作單、當日成交、帳戶部位；只有唯一歸屬且去重後的成交可回補至原策略。對側是否仍工作、是否已成為限價出場，以及停損／時段平倉是否已送，均不得由檔案單方面推定；不一致時隔離並禁止自動恢復送單。

模擬與實盤各自的策略頁籤使用固定寬度控制項，顯示均線開關、參考商品、N 設定／實際值、兩側價位、停損與週期狀態。共用紀錄保存設定／實際 N、bid1/ask1、SMA 與趨勢方向、有效簿／拒絕原因、每張原始委託與有效成交用途、停損觸發、精確撤單、終態水位、策略部位和成本。不得建立策略專屬帳本或僅依自由文字原因分析。尚未取得的券商延遲／開平倉資料必須標示不可得，不得補造。

## 驗收與研究門檻

1. 均線開／關、中性、未暖機、過期參考、不同商品設定均有可重現測試；關閉時不要求 225／225M 同向或存在。
2. 向上／向下平移 N、縮減至 bid1／ask1、縮減為 0、完全無可行位移、tick 對齊與價差／相對停損距離不變均有單元測試；送單檢查只宣稱檢查時點的被動性。
3. 同輪兩張原單持續工作；一側成交後對側保留相同 client/broker ID；第二側成交只計作一次完整出場，沒有額外券商 TakeProfit 單。既有其他策略 OCO 測試維持通過。
4. 停損觸發時撤對側、等終態及最終累積量對平、依剩餘部位只送一次市價；對側已全數或部分成交、撤單拒絕、晚到／重複回報、市價拒絕等路徑逐一測試。
5. `PositionEffect.Auto` 對此模式的兩張實盤限價有 fake gateway 映射測試；兩個策略同商品同時運作、反向部位、重啟回補與未知歸屬隔離均有測試。測試不等於實際券商驗證。
6. 收盤前撤單／平倉、暫停、刪除及異常保護回歸通過；不得在該時段再開新輪。
7. 使用相同封存、手續費與成交模型重播目前基準與候選。共用紀錄及 MR Python 分析輸出須比較訊號漏斗、成交、完整交易、淨損益與額外 0／1／2 跳反向滑價；不得因交易數或單次獲利宣稱可實盤。
8. Debug／Release 建置及相關 smoke suites 通過，記錄既有警告；整個驗證期間不得送出真實券商委託。實際券商 Auto 開平倉與快速雙側成交時序，仍需另經明確授權的受控驗證。

## 非目標與限制

本次不調整 H、F、K 或 R 的正式預設值，不自動追價、改價或增加口數，不自動優化 N，不更動其他策略或共用損益公式。雙張實盤送單無法具備交易所原子性；本機報價檢查與 fake gateway 測試也無法保證網路延遲後仍不立即成交。先前候選策略的負淨收益不會因這份規格而轉正；必須以實際實作後的同資料對照回測重新評估。
