# 內外盤順勢交易策略設計

日期：2026-09-27

策略顯示名稱：內外盤順勢交易

策略識別名稱：`TradeFlowTrend`

狀態：交易規則已逐項確認；本書面規格及第 10 節補充預設值供使用者整體審閱。尚未實作策略、執行回測或驗證券商委託。

## 1. 目的與範圍

交易 `225MC`，以 `225M` 與 `225` 的內外盤成交力道，以及 `225M` 的快慢價格均線判斷多空。條件成立便送出第一檔限價委託，僅往追價方向調整。固定停損、固定停利、SAR、趨勢轉弱及盤末收尾共用一套依價差選擇 IOC／ROD 的平倉流程。

本策略整合既有 `StrategyFramework`、策略中心、共用帳本、紀錄器與回放功能。每個實例各自保有部位、委託、參數及績效；同商品的其他策略與手動單不計入本策略。

本文件的第 2～9 節整理對話中已確認規則；第 10 節是為使設計可實作而提出的補充預設值，尚未宣稱使用者已逐項同意。數值皆為研究基準，沒有獲利或穩健性驗證結果。

## 2. 商品與成交分類

| 用途 | 商品 |
|---|---|
| 實際下單 | 225MC |
| 主要訊號、均線 | 225M |
| 參考確認 | 225 |
| 觀察與留存 | 三個商品各自計算全部表格、均線及資料品質 |

依同一商品成交前最近的有效第一檔報價分類；成交量以每筆真實成交事件的數量累加。

```text
if TradePrice >= AskPx: Up
else if TradePrice <= BidPx: Dn
else: Zero
```

前提為買賣報價存在、為正、`BidPx < AskPx` 且未過期。報價缺漏、過期、鎖價／交叉、成交量非正、順序不明等情況記為無法分類及具體原因，不歸入 Zero。

只在 Trade 事件增加成交量；Book 事件不重複計入最後一筆成交。保存實際選用的報價事件識別及年齡，不使用成交之後的報價回填分類。不得以單純價格上漲／下跌分類代替本規則。

## 3. 三張觀察表

三張表格為 30s、60s、180s；每張欄位固定為 `225 / 225M / 225MC`，列固定為：

```text
Up
Zero
Dn
Real(Up-Dn)
Avg(Up-Dn)
Max(Up-Dn)
Min(Up-Dn)
```

對商品 p、視窗 W，在截止時間 t 的有效分類成交量分別為 U、Z、D：

```text
V = U + Z + D
Up   = 100 * U / V
Zero = 100 * Z / V
Dn   = 100 * D / V
Real = Up - Dn
```

Up、Zero、Dn 的單位為百分比；Real、Avg、Max、Min 的單位為百分點。若 V = 0，結果為 null，畫面顯示 `--`，不得補零。另保留無法分類的成交量、占全部成交量比例及有效樣本數。

### 3.1 Real：移動窗格

每秒刷新最近 W 秒的成交量占比及 Real。三商品獨立計算，不直接合併不同商品的成交量。

### 3.2 Ri：固定間隔取得歷史樣本

| 表格 | Ri 採樣頻率 | 歷史格數 N | Avg／Max／Min |
|---|---|---|---|
| 30s | 每 30 秒記錄一次 Real | 60 | 最近 60 個固定區間的有效 Ri |
| 60s | 每 60 秒記錄一次 Real | 30 | 最近 30 個固定區間的有效 Ri |
| 180s | 每 180 秒記錄一次 Real | 10 | 最近 10 個固定區間的有效 Ri |

三組預設皆代表最近 30 分鐘。Avg 是 Ri 的算術平均，不再依各區間成交量加權；Max、Min 取同一批 Ri 的極值。即時 Real 在採樣點之外不加入這批歷史統計。

補充設計採台灣時間自然時鐘對齊，區間為左閉右開 `[start, end)`；截止邊界先封存前一區間，再處理邊界起的新事件。Ri 使用封存截止時的 Real，避免同一成交落入兩個固定區間。

歷史容器保留 N 個時間格，無成交格保留 null，不能用更早資料補足 N 筆而使觀察時間超過 30 分鐘。啟動或重連後的首個不完整區間標記為 partial，不作完整 Ri 使用。顯示有效筆數／目標筆數及暖機狀態；不足 N 個有效樣本時 Avg／Max／Min 可顯示暫算值，但必須標示暫算。是否允許使用暫算值進場，依第 10 節的補充預設。

## 4. 均線與進場

每秒取該商品當下最後成交價一筆，預設 SMA 快線 30 筆、慢線 120 筆。均線類型及快慢週期可修改；快線週期須小於慢線。

三商品各自計算均線。現行進出場判斷使用 225M 均線，不要求 225 或 225MC 均線額外確認。

預設使用 30s 表：

| 條件 | 做多 | 做空 |
|---|---|---|
| 225M 均線 | Fast > Slow | Fast < Slow |
| 225M Real | Real > 0 且 Real > Avg | Real < 0 且 Real < Avg |
| 225 Real | Real > 0 且 Real > Avg | Real < 0 且 Real < Avg |

每欄所有條件成立才可進場。相等不成立。預設正負門檻與 Real 相對 Avg 的差值門檻均為 0，保持嚴格大於／小於；觀察表週期及差值門檻可設定。60s／180s 預設供觀察及研究，未選作訊號來源時不加上額外過濾。

「立即進場」表示訊號在既定計算頻率下成立便送單，不再等待持續數秒確認，也不等待下一個 Ri 固定區間結束。成交仍依回報確認。

進場還須處於啟用時段、完成必要暖機、資料有效，且該策略實例空手、沒有有效或結果未明的進場／平倉委託。不得僅因帳戶商品淨部位為零便認定策略空手。

## 5. 進場委託與單向追價

| 動作 | 做多 | 做空 |
|---|---|---|
| 首筆委託 | 225MC 買 1，限價 ROD | 225MC 賣 1，限價 ROD |
| 追價 | 買 1 上升才上移到新買 1 | 賣 1 下降才下移到新賣 1 |
| 反向移動 | 買 1 下跌不往下改價 | 賣 1 上升不往上改價 |
| 訊號失效 | 撤銷尚未成交進場單 | 撤銷尚未成交進場單 |

買 1 下跌／賣 1 上升不代替成交回報，仍須核對實際成交及剩餘口數。新送或改價的進場單以最新有效報價檢查不跨對手價；在網路傳送期間的市場變化不能視為券商原生 post-only 保證。

優先沿用共用框架可確認歸屬的改價能力；若採撤單重掛，必須完成撤單與最終累計成交量核對後，才送替代單。追價期間多次報價更新合併為最新目標，不能每次更新各自送一張新單。

多口部分成交後仍監控已成交部位的保護條件。任何出場條件觸發，先取消剩餘進場單並核對晚到成交，再由同一平倉流程處理全部已確認部位。

## 6. 出場觸發

以本策略已確認的實際持倉均價 E、225MC 最小跳動 T 計算：

```text
多單可平倉浮盈 tick = (Bid1 - E) / T
空單可平倉浮盈 tick = (E - Ask1) / T
```

| 條件 | 規則 | 預設 |
|---|---|---|
| 固定停損 | 多單 Bid1 <= E - S*T；空單 Ask1 >= E + S*T | S = 6 tick |
| A 固定停利 | 可平倉浮盈 >= P | P = 50 tick |
| B SAR | 可平倉浮盈達啟動門檻後，以 SAR 判斷出場 | 啟動 8 tick，SAR 5 秒 K |
| C 趨勢轉弱 | 見下表 | 30s Real、225M 均線 |
| 盤末 | 到達該盤別設定結束時間 | 日 14:25、夜隔日 04:40 |

以上任一成立便啟動平倉，不要求 A／B／C 同時成立。出場觸發一旦成立，直到部位與委託歸零前均保留平倉意圖，不因價格反彈、訊號恢復或重新跨過均線而取消。

### 6.1 C 趨勢轉弱

| 部位 | 全部成立才觸發 C |
|---|---|
| 多單 | 225M Fast < Slow，且 225M Real < 0、225 Real < 0 |
| 空單 | 225M Fast > Slow，且 225M Real > 0、225 Real > 0 |

C 不比較 Avg。缺少有效參考資料時不虛構 C 成立；固定價格保護、盤末與資料異常管理仍各自運作。

### 6.2 SAR 具體計算約定

補充設計使用 225MC 真實成交聚合的已完成 5 秒 OHLC K 線，不能只拿每秒最後成交價重建遺失的高低點。SAR 從暖機開始持續計算，獲利達 8 tick 後才啟用該筆部位的 SAR 出場判斷，啟用後持續到該筆部位完全結束。

已完成 K 線更新 SAR；已啟用的出場線以即時有效買賣價監控：多單 Bid1 <= 有效 SAR 線、空單 Ask1 >= 有效 SAR 線即觸發。SAR 已轉為部位的反向趨勢時也觸發 B。B 只發出平倉意圖，不在同一回呼中反手建立新部位。

SAR 數學基準採 Wilder 遞推、極值點與前兩根高低點限制；初始方向以兩根已完成 K 線收盤價比較，收盤價相等時等待可判定方向的完整 K 線。先用起始 AF=0.02、步進=0.02、上限=0.20，三項可調。初始化、相等邊界、反轉及缺 K 行為須固定並以人工例證驗證 C#／Python 一致。這些初始 AF 值與演算法參考 [TradingView 官方 SAR 說明](https://www.tradingview.com/support/solutions/43000502597-parabolic-sar-sar/)，不是本策略已驗證的最佳參數。

無成交 K 線不捏造 OHLC；保留缺格標記。SAR 資料超過允許新鮮度時不使用舊線假裝有效，並顯示資料原因；部位的固定停損及收尾流程不因此解除。

## 7. 所有出場共用的 IOC／ROD 規則

`SpreadTicks = (Ask1 - Bid1) / TickSize`，比較未經顯示四捨五入的值。

| 平倉方向 | SpreadTicks < 2 | SpreadTicks >= 2 |
|---|---|---|
| 空單買回 | 限價 Bid1 + 10*T，IOC | 限價 Bid1 + 1*T，ROD |
| 多單賣出 | 限價 Ask1 - 10*T，IOC | 限價 Ask1 - 1*T，ROD |

恰好 2 tick 屬 ROD。10 tick 是送單價格偏移，不是停損觸發距離。2／10／1 皆列為可設定參數，但比較邊界保持 `<` 與 `>=`。

### 7.1 IOC

收到該張 IOC 結束回報，且最終累計成交量與已交付成交一致後，若仍有剩餘部位，立即讀取最新報價、重新判斷價差並送出下一張適用委託。部分成交只重送剩餘口數。價差擴大至 >=2 時下一張改為 ROD。

「立即」指確認前筆終結後的下一次可送單處理，不增加策略等待秒數。拒單、斷線、送單結果不明或缺少最終成交水位不當作零成交而盲目重送；保留平倉意圖並進入相應查詢／對帳狀態。沿用券商與共用執行層速率限制，紀錄其造成的延遲。

### 7.2 ROD

買回單只在買 1 上升時改掛新買 1+1 tick；賣出單只在賣 1 下降時改掛新賣 1-1 tick。反向變動維持原掛價並等待成交回報。

價差縮至 <2：要求撤銷 ROD，確認撤單及其最終成交水位，重新讀取最新部位及價差後，對剩餘部位送 IOC。若撤單等待期間價差又擴至 >=2，按最新價差重建 ROD，不使用舊的縮窄訊號強送 IOC。

平倉流程中每個方向最多一張有效或結果未明的工作委託。出場條件重複觸發不建立第二套平倉流程。晚到成交、重複回報及撤單失敗由共用歸屬路由與去重水位處理。

### 7.3 原因與角色

固定停損使用 `StopLoss`；A 使用 `TakeProfit`；B、C、盤末及資料管理性出場使用 `Flatten`，並保存具體 `SarExit`、`TrendReversal`、`SessionEnd` 等原因。

同一事件多個條件成立時保存完整觸發集合；主要原因依盤末、固定停損、A、B、C 排序。平倉中後來出現的更高優先原因可更新原因，不新增平倉單。以上只是診斷歸因，不影響任一成立即出場。

## 8. 日夜盤

時區固定採台灣時間 `Asia/Taipei`（Windows 對應 `Taipei Standard Time`），不得依電腦顯示時區猜測。

| 盤別 | 策略可新倉區間 | 結束時執行 |
|---|---|---|
| 日盤 | 07:50 <= time < 14:25 | 禁止新倉、撤進場單、共用流程平倉 |
| 夜盤 | 16:10 <= time < 次日 04:40 | 同上 |

市場時段 07:45～14:45、16:00～隔日 05:00 來自本次使用者提供資料，用於說明預設結束時間為收盤前 20 分鐘；本設計沒有將其宣稱為已重新查證的官方最新交易日曆。

日、夜盤啟閉時間分別可修改；另提供各盤別啟用開關。以四個明確時間為權威設定，避免同時保存「提前分鐘」又保存「結束時間」而產生衝突。每夜盤綁定開始日期，跨午夜後不重啟新盤別。週末／休市／特殊交易日依共用商品交易日曆處理；無法確定是否可交易時不開新倉。

時間到即鎖定收尾狀態，盤末也套用第 7 節規則。尚未成交完畢時持續平倉及核對，不能因時間超過結束而停止保護。下一盤別開始仍未對帳完成時禁止新倉。只有策略部位、有效委託、未確認委託均為零才完成該盤別收尾。

因此 14:25／04:40 是停止新倉及觸發收尾的時間；採 ROD 時，實際平倉完成時間取決於市場成交，不能把這個設定宣稱為成交完成保證。每次必須記錄設定截止與實際完成之差。

盤末判斷使用共用時鐘心跳，不能等待下一筆成交才發現截止。暫停、有部位及斷線期間仍保留時鐘與保護流程。

## 9. 參數與介面

模擬與實盤策略中心各有專屬頁籤。可調整項目包含：

- 口數、日夜盤啟用及四個啟閉時間。
- 均線種類 SMA／EMA、快慢週期；採樣間隔固定一秒。
- 30／60／180 秒觀察表的 Ri 保留筆數，預設 60／30／10；修改後揭露實際觀察長度。
- 進場訊號表（30／60／180）、Real 方向門檻、相對 Avg 差值門檻、C 的訊號表與反向門檻。
- 固定停損 6、A 固定停利 50、B 啟動浮盈 8 tick；SAR K 線秒數及 AF 三參數。
- 價差界線 2、IOC 偏移 10、ROD 偏移 1 tick。
- 資料新鮮度、樣本完整性、手續費及共用策略單日虧損額度。

A／B／C 在本版全部啟用，保持使用者指定的 OR 關係。不是因其參數值為 0 就暗中停用；停損／停利距離必須為正。

表格維持指定的三表版型，附單位、實際採樣時間、有效格數、資料年齡、暖機狀態及未知分類比率。另顯示三商品快慢均線、SAR、策略部位均價、觸發價格、IOC／ROD 狀態、剩餘口數與當前原因。

參數與狀態控制項採固定寬度；視覺沿用 Dashboard。可編輯 WinForms 控制項配置放在 `Designer.cs`。勝率、平均獲利點數、平均虧損點數、使用者定義獲利因子由共用帳本提供，無值顯示 `--`。

保存與載入參數組；每次執行揭露完整有效值及版本雜湊。任何參數更新都留下舊值、新值與生效時間，不能只留下 UI 最後的文字。

| 均線沿用最後成交價 | 允許年齡不超過 5 秒；超過則樣本缺失並阻擋新倉，不能製造新成交量 |
| 跨參考商品報價時間差 | 不超過 2,000 ms，可調；以實際 Book 更新時間衡量 |
| SAR 有效資料年齡 | 預設 2 個 SAR K 線週期；超過時揭露資料失效，不使用舊線觸發 B |
| 參數修改生效 | 本次執行固定有效參數快照；修改先儲存新組，部位及委託歸零後重新啟動生效 |
| 暫停／恢復 | 空手撤進場單；有部位繼續保護。恢復需明確操作，重新檢查資料與時段 |
| 成本與單日虧損限額 | 取共用框架的明確有效設定並揭露；實盤設定缺失時不允許啟動，不能由新策略默認無限額 |

參數約束：快慢均線週期 1～3,600 秒且快<慢；SAR K 線 1～300 秒；Ri 保留數 1～3,600；停損／停利／SAR 啟動 1～10,000 tick；AF 滿足 `0 < Start <= Max <= 1` 且 `0 < Step <= Max`；方向與 Avg 差值門檻分別為 0～100、0～200 百分點；ROD 價格偏移為正且小於價差切換界線，IOC 偏移不少於界線。時段不得在同一實例重疊，日盤不跨日，夜盤明確跨日。均線改為 EMA 時以完整 N 個有效秒樣本的 SMA 初始化。

## 12. 模擬與回放契約

所有結果須清楚標記執行模型。既有 ROD 嚴格穿價規則保留：僅觸及不算成交；不得假設掛上第一檔就已成交或具有隊列優先權。

新增限價 IOC 模型必須在共用執行層區分一次撮合與未成交餘額終結，不能把 IOC 留成長期工作單。候選研究模型：送出時以最新有效可成交對手檔檢查嚴格穿價、成交口數不超過該檔已知可用數量，沿用保守的委託限價作模擬成交價，餘額取消。未觀察到有效價量時不虛構成交。

同一報價快照的數量不得被重複使用；無新增報價與可用數量時，回放將無新增結果的重試合併為等待下一市場事件，不能同步遞迴無限送單。此模擬合併與真實 IOC 回報驅動立即重試的差異，必須記入模型說明，不能據此宣稱已驗證真實延遲、成交率或排隊位置。

即時原始封存、特徵計算與回放共用同一時鐘語意；不得使用電腦現在時間計算歷史的區間、暖機或收尾。若紀錄缺少 Book 新鮮度、成交數量或必要商品，輸出資料不足而不是補造特徵。

## 14. 驗收範圍

1. 分類：成交恰等於 Ask／Bid、價差中間、無效報價、成交後報價、重複事件及 Book 不增加成交量。
2. 統計：移動 Real 與固定 Ri 不混用；30/60、60/30、180/10；邊界事件只入一次；量加權占比與 Ri 算術平均；零成交／缺格不拉長 30 分鐘。
3. 時序：1 秒採樣、缺成交、快慢均線暖機、5 秒 OHLC、SAR AF 極限與反轉；8 tick 啟用鎖定、跳價同時觸發 A/B、回放無前視。
4. 訊號：多空完整條件、零與均線／Avg 相等、C 不需要 Avg、缺值不產生假訊號。
5. 執行：進場只向積極方向追價、不反向退價；2 tick 恰好走 ROD；買賣公式正確；ROD 撤單期間成交；IOC 部分成交、最新價差重新選模式、同快照不無限回放重試。
6. 歸屬：多口、跨策略同商品、反向部位、重複／晚到回報、拒單、取消失敗及最終水位未確認，不產生過量或反向部位。
7. 時段：07:50、14:25、16:10、隔日04:40 的精確邊界；休市、跨午夜、無行情心跳、盤末未成交持續保護及禁止重開。
8. 參數：種類、範圍、跨日時間、變更生效、SMA／EMA 暖機與參數摘要一致。
9. 紀錄與分析：相同輸入可重現、所有接受／拒絕門檻有證據、資料不足不排名、完整交易成本與績效正確、樣本切分無洩漏。
10. UI 與建置：模擬／實盤頁籤及三表、Designer 可編輯、缺值顯示；聚焦冒煙測試及 Debug／Release 建置；實盤只以替身驗證映射與生命週期，不送券商測試單。
